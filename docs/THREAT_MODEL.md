# HOLD threat model

Task 3.14. One row per asset. The status column says whether a control is in the shipped code
(with the commit that landed it) or planned under a named PLAN.md task; a planned control is not
a claim. Residual risk is what remains after the controls listed, stated plainly.

| Asset | Threat | Control | Status | Residual risk |
|---|---|---|---|---|
| Rules registry (`rules/*.yaml`) | A quote is composed rather than copied, or a number in `params` drifts from its source, and the verdict card cites a sentence the statute never said | Every quote is a verbatim substring of a committed snapshot under `rules/sources/`; every numeric param is stated by the quote, by a second verbatim fragment, by a derivation from evidenced numbers, or is a counted assumption; PENDING is refused; the records using each marker are pinned by name | In place (0feb489, 2bda6c8, 90f4d35), CI job API tests | A fragment proves a sentence exists in the source, not that it belongs to the param; the pinned set makes a new use a review event, not an automatic refusal. One record (sagaftra.org) is UNVERIFIABLE and excluded from claims |
| Legality verdict | The CP-SAT core omits a violation that also holds, or names a rule that does not apply, and a production trusts it | D13: the independent plain-Python checker enumerates violations and is the source of truth; the solver only explains; a LEGAL day returns a witness call sheet the checker re-reads; the checker and the solver share one set of applicability predicates | In place (23c699b, 0535519, 8dd9ebe, cdea6ab) | On an ILLEGAL day the checker judges the crew window (a labeled proxy); a crew meal is modeled once per day; wraps past midnight are refused as UNDETERMINED rather than judged |
| Headline numbers | A typed figure in the README, the video or the submission drifts from what the code computes | `docs/FACTS.json` is written only by `scripts/facts.py` from a real run; CI recomputes the deterministic fields and scans README and docs for hold-day, illegal-day, benchmark and payroll figures | In place (242bed8) | Surfaces outside the repo (video narration, the submission form) depend on the pre-submit checklist reading FACTS, not on CI |
| Solver availability | A flood of `POST /api/solve` starves the instance or blocks `/api/status` | One-worker thread pool per instance, a per-solve CP-SAT time limit (`HOLD_SOLVE_TIME_LIMIT_S`), `--max-instances=1`, status served from cached files | In place (1182cb3, 242bed8); the Cloud Run flags live in `deploy.yml` | No authentication and no rate limit on the public demo: a flood queues jobs in memory until the instance restarts. Acceptable for a judged demo, stated here |
| Extraction (Gemini through ADK) | Untrusted call-sheet text steers tool calls, or a hallucinated schedule is solved without a human seeing it | The ADK API server is never mounted (D12): a `Runner` sits behind `POST /api/extract`, which refuses with 503 until the agent exists and returns a labeled fixture under `HOLD_FAKE_EXTERNALS=1` | In place (1182cb3): route and refusal | Planned, PLAN.md 3.1 and 3.3: `before_tool_callback` allowlisting three tools with Pydantic-validated arguments, a 30 s timeout, at most three model calls per request, and a human Confirm before any extracted schedule is solved. Until they land, the live path does not exist |
| Set events | A forged event edits the schedule and triggers a re-solve | Events are validated against `SetEvent`; each carries `source` and the exact change made; the re-solve is a new job and the base job is kept | In place (1182cb3) | Anyone with the URL can post an event (no auth); the in-process bus is the demo path, the Confluent leg (PLAN.md 4.1) adds API-key transport but not end-user auth |
| Secrets and credentials | A key lands in the repo or an image | No service-account JSON: Workload Identity Federation for deploy; runtime secrets in Secret Manager; `.env` gitignored with a tracked `.env.example`; gitleaks over the full history in CI; `git ls-files` checked before every push | In place (deploy.yml, ci.yml) | A secret pasted into a commit message or a doc is caught only by gitleaks patterns |
| Dependencies | A malicious or license-incompatible package | `uv.lock` pins every dependency; Socket Security report and a license guard in CI | In place (ci.yml) | Transitive updates on `uv sync` outside the lock are not covered |
| Minors' data | Real children's schedules or identities in a public repo or demo | The demo is constructed data (D8) and carries `constructed: true` into every response; no third-party contact detail reaches the repo | In place (data/demo, schemas) | None for the repo; a production deployment would need its own data handling, outside this project |
| Browser origin | A hostile page calls the API with a user's cookies | CORS allows named origins only (`capacitor://localhost`, the local dev hosts, the Cloud Run origin) | In place (api/main.py) | The API has no cookies or sessions today, so the exposure is the unauthenticated surface above, not credential theft |
| CI as evidence | A green check that did not run the assertion it claims | Every gate runs bare with its exit code checked; guards fail rather than skip; the quote check fails on PENDING; the FACTS check recomputes rather than compares strings | In place (ci.yml, tests) | The Cloud Run deploy job passes with a notice while the GCP secrets are absent (6b787f6); it deploys nothing until PLAN.md 0.1 |

## Out of scope

Native shells (PLAN.md 3.8 onward) and the web app (Deem's lane) are not modeled here yet; the
table gains rows when they ship. Nothing in this document is a claim about the runtime agent
until PLAN.md 3.1 to 3.3 are marked DONE in the task table.
