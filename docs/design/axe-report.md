# Accessibility audit

Run with axe-core 4 against the production build, on every route. It is a test, not a script:

    cd web && npx playwright test tests/e2e/a11y.spec.ts
    cd web && node scripts/measure_contrast.mjs        # the contrast table

`web/tests/e2e/a11y.spec.ts` runs in the same continuous integration job as the rest of the
end-to-end suite, against the built app served by the same origin as the API, so it cannot
quietly stop running.

## Result

**Zero violations of any impact**, on `/`, `/board`, `/day/3`, `/import` and `/judge`. The task
asked for zero serious or critical on three routes. The assertion in the test is the stronger
claim this page makes, so the sentence above and the gate cannot drift apart.

`axe-report.json` is the machine output and is an empty array.

## What it caught, and what that says about self-audits

The first run reported **146 serious contrast violations per pass**, at a point when the judge
page was already publishing a contrast table claiming AAA throughout.

Two separate mistakes, and the second is the instructive one.

1. **A token genuinely failed.** `bone-faint` rendered `#73716e` on `#101010`, which is
   **3.91:1**: below AA, let alone the AAA the verdict is held to. It was used for every section
   label, source line and citation on the site.

2. **The published table did not contain that pair.** It listed the pairs that had been designed
   deliberately and omitted the token that had been introduced casually. An audit that only
   checks the pairs you already believe in cannot fail.

And a third, found while fixing the first two: **every figure in that table was wrong anyway.**
It had been computed by hand from the OKLCH values. Measured from the painted pixels, primary
text is 16.89:1 and not the 13.6:1 claimed, the INT NIGHT strip is 9.85:1 and not 7.7:1. The
errors happened to be flattering, which is exactly why nobody noticed them.

The table is now generated by `web/scripts/measure_contrast.mjs`, which reads the rendered
pixels, and the one pair that is AA rather than AAA is listed rather than left out.

## The finding that came from making it a test

This page claimed zero violations for weeks while the harness that produced that number lived in
a scratch directory and had run exactly once, by hand. Two judged surfaces changed after that run:
the judge page grew a step and the board grew the agent panel.

Turning the claim into a test found a **critical** violation on `/import` on the first execution.
The camera scan control is a file input hidden with `sr-only` and driven by a visible button. It
is still a form control a screen reader reaches, and it had no name, so axe reported "form
elements must have labels". It now carries an `aria-label`.

The shape is the same one this page already describes twice. There, an audit checked only the
pairs its authors already believed in. Here, an audit ran once and then described a product that
kept changing underneath it. A number in a document is a claim about a moment; a number a test
recomputes is a claim about now.

## The other class of finding

Every remaining failure after the token fix came from `opacity-*` applied to text. Opacity
multiplies the effective contrast down, so a dimmed label is a colour that no token table
describes and no audit of tokens will ever catch. Text hierarchy now comes from tokens and
weight; opacity is used only on things that are not text.

`<dl>` groups were also being used for layout rather than as definition lists. They now contain
real `<dt>` and `<dd>` pairs.
