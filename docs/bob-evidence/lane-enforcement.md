# Lane enforcement record

Every fact here is read from a committed file; nothing is asserted from memory.

## The lanes

`.bob/custom_modes.yaml` defines five write-scoped custom modes. Each mode's `fileRegex` is the
only set of paths that mode may edit:

| Mode | fileRegex |
|---|---|
| `solver-engine` | `^(api/(hold\|tests\|routes)/\|pyproject\.toml$\|uv\.lock$\|bench/\|rules/\|scripts/\|data/)` |
| `agent-runtime` | `^(api/(agents/\|main\.py$)\|Dockerfile$\|api/hold/(streaming\|mcp_server)\.py$)` |
| `mobile-shell` | `^web/(android\|ios\|src/native)/\|^web/capacitor\.config\.ts$` |
| `frontend` | see `.bob/custom_modes.yaml` (web paths outside the native four, `docs/design/`) |
| `evidence-writer` | see `.bob/custom_modes.yaml` (`docs/` outside design, `README.md`, `specs/`, `security/`) |

Per-mode rules live under `.bob/rules-<mode>/AGENTS.md`.

## What enforces them

`api/tests/test_bob_lane_enforcement.py` parses the `fileRegex` values from the modes file with
the standard library and asserts the allow and refuse matrix from PLAN.md task 0.14 (twelve
cases: the frontend mode refuses `api/hold/`, `web/android/` and `docs/bob-evidence/`; the
solver-engine mode refuses `web/src/`; the mobile-shell mode refuses `web/src/board/`; each mode
allows its own paths). The CI job `Bob attribution current` in `.github/workflows/ci.yml` runs
that file together with `api/tests/test_bob_attribution.py` on every push and pull request, so a
regex change that widens or breaks a lane fails the build.
